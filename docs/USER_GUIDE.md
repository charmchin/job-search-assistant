# 求职助手使用手册

求职助手不是岗位收藏夹。它的目标是把一个招聘链接变成三个清晰结果：这个岗位是否值得投入、下一步具体做什么、最晚什么时候完成。

## 1. 启动与关闭

### 1.1 首次安装（推荐）

安装前请确认：

- 使用 macOS 13 或更新版本（应用入口要求）；
- 已安装 Node.js 22.13 或更高版本，并可在终端执行 `node --version` 和 `npm --version`。双击脚本不会自动安装 Node.js；若提示找不到 Node.js，安装后重新打开终端再试；
- 首次安装需要联网下载 npm 依赖；AI 和公开链接读取也需要相应网络连接，手动录入与已保存数据的管理不依赖 AI；
- 项目已放在准备长期保留的位置。应用入口依赖这个源文件夹，不是自包含安装包；安装后不要直接移动或删除项目。需要迁移位置时，先在旧目录运行 `stop.command` 和 `uninstall.command`，再移动项目并重新安装，数据库仍保留。

在 Finder 中进入项目文件夹，双击 `install.command`。它会完成生产构建，并安装：

- `~/Applications/求职助手.app`：可由 Spotlight 搜索，也可拖入 Dock；
- `~/Library/LaunchAgents/com.local.zhaopin-assistant.plist`：登录 Mac 后自动启动后台服务，并在异常退出时恢复。

安装完成后，日常只需像普通 Mac 软件一样打开“求职助手”。应用图标负责确认后台服务并打开工作台，不会显示终端窗口。关闭浏览器窗口不会停止服务，截止提醒仍可继续运行。

如果希望固定到 Dock，在 Finder 中打开个人目录的“应用程序”，将“求职助手”拖入 Dock。

应用原名“求职工作台”。更新安装会将本项目的旧入口迁移为“求职助手.app”，不会另建数据库或更换钥匙串。若 Dock 仍显示旧名称或问号，移除旧 Dock 图标，再将“求职助手”拖入即可；移除 Dock 图标不会卸载软件或删除数据。

### 1.2 启动、停止和卸载

- 日常启动：从 Spotlight、`~/Applications` 或 Dock 打开“求职助手”；
- 完全停止：双击 `stop.command`，数据不会删除，但停止期间不会发送提醒；
- 停止后恢复：再次打开“求职助手.app”，或双击 `start.command`；
- 移除应用入口：双击 `uninstall.command`，登录启动项和应用入口会被删除，数据库与项目源文件仍会保留。

`start.command` 是免安装和故障恢复入口。首次启动会安装依赖、迁移数据库并构建应用，时间会比平时长；重复执行不会启动第二个服务。`.app` 和脚本使用同一套版本检查：未变化时直接打开，源码或迁移更新时先停止旧服务、迁移、构建并启动新版本，不会因为服务已运行而跳过更新。更新会短暂停止提醒，请先保存正在编辑的内容。

需要明确重启当前版本时，在终端运行 `./start.command --restart`；未变化的代码不会重新构建。打开入口与更新检查是一体的，强制重启则是显式操作。登录启动项只运行上一次成功构建；更新源码后请打开应用入口完成版本检查，不要把登录自动启动当作自动升级。

如果系统阻止 `.command` 脚本运行，可右键脚本、选择“打开”，再在安全提示中确认。

也可以在“终端”中运行：

```bash
cd "/实际的项目文件夹路径"
./start.command
```

将示例路径替换为自己的项目位置，也可以输入 `cd ` 后把 Finder 中的项目文件夹拖进终端，再按回车。

启动窗口会显示当前步骤；失败时不会立即消失，而会给出中文原因。安装日志位于 `~/Library/Application Support/ZhaopinAssistant/install.log`，启动流程日志位于同目录的 `launcher.log`，服务日志位于 `server.log`。

从应用图标启动失败时会弹出中文对话框，可点击“查看日志”。若提示端口被占用，不会打开或强制关闭其他程序；如果是自己用 `npm run dev`/`npm start` 启动的服务，请先在对应终端按 Ctrl+C，再打开应用。启动器不能自动终止未受其管理的旧版或开发服务。

多个启动/停止操作会排队。遇到“另一个操作尚未完成”，请等待后重试，不要删除正在使用的锁文件。构建失败不会启动不完整版本，数据保留；修正代码或依赖问题后重新打开入口即可。应用目前仍在默认浏览器中打开，不是独立 WebView 桌面窗口。

## 2. 推荐的第一次设置

1. 打开“设置与数据”。
2. 将“停滞复查天数”保持为 5 天，或按自己的投递节奏修改。
3. AI 提取是可选项。没有兼容接口时无需配置，链接适配器与规则提取仍可工作。
4. 在“材料库”添加当前简历、成绩单、作品集等文件。应用只记录路径，不复制和上传文件。

### 可选：配置 AI 提取

在“设置与数据”填写以下项目，再点击“保存设置”：

1. “兼容接口地址”：填写服务商提供的 OpenAI 兼容基础地址，通常以 `/v1` 结尾。不要填写完整的 `/chat/completions` 地址，应用会自动追加该路径；留空使用默认地址 `https://api.openai.com/v1`。
2. “模型名”：填写该服务商支持、且自己的密钥有权限使用的准确模型名。
   使用 DeepSeek 官方接口时，地址可填 `https://api.deepseek.com`，Flash 模型 ID 填 `deepseek-flash`；官方 Flash 展示名称会在调用时自动规范化。
3. “API 密钥”：首次使用时填写；以后留空表示不更改已有密钥，**不是删除密钥或关闭 AI**。密钥存入当前 Mac 的钥匙串，不保存到业务数据库。
4. 保存后用一段不含敏感信息的招聘正文尝试“整理岗位信息”，核对界面显示的 AI / 规则模式及提示。“已保存”只表示配置保存成功，不代表接口已经连通。地址、权限、网络或响应格式不兼容时会回退规则模式，仍可手动纠正并保存。

希望停止调用 AI 时，清空“模型名”并保存；不要只清空密钥输入框。维护人员若通过环境变量设置了 `OPENAI_MODEL`，清空界面模型名仍会使用该环境配置，需要由维护人员移除后重启服务。

隐私边界：启用 AI 后，参与整理的招聘正文会发送给你配置的接口服务商，可能产生该服务商的费用。不要粘贴身份证号、私密沟通或其他不愿外发的信息。材料库文件不会自动上传；但若自行把文件内容粘贴到招聘正文，它仍会作为正文发送。关闭 AI 后使用本地规则整理；提交链接仍会访问对应公开招聘网站，单独粘贴正文则不读取该来源链接。

## 3. 收集岗位

点击右上角“收集岗位”。

### 3.1 使用招聘链接

把公开岗位链接粘贴到“招聘链接”，点击“整理岗位信息”。已适配的招聘站点会直接读取岗位数据；腾讯招聘岗位详情页会读取其官方岗位接口，不再把动态空页面误判为网络错误。

静态网页正文不足时，应用会自动加载动态网页，最多等待 40 秒。成功后显示“动态网页 · 已读取”；国聘详情页会保留岗位职责、任职条件及报名截止信息。

如果页面需要登录、验证码、岗位已下线或加载超时，界面会说明原因并保留链接。此时复制招聘页里的岗位名称、岗位职责、任职要求、截止日期和材料要求，粘贴到“招聘正文”后再次整理。

动态读取需要 Playwright Chromium 或本机安装的 Google Chrome。提示组件无法启动时，可在项目目录运行 `npm run browser:install` 安装 Chromium。浏览器读取使用独立会话，不会使用你平时浏览器的登录状态。

### 3.2 使用招聘正文

也可以不填链接，直接粘贴邮件、公众号或群消息里的招聘正文。文本越完整，提取结果越可靠。

### 3.3 核对草稿

系统会按来源链接或“公司 + 岗位”检查机会库；重复时提示“该机会已在机会库中，请勿重复添加。”，可点击“查看已有机会”打开原记录。链接中的常见追踪参数、片段及公司岗位的大小写、空白和全角标点差异不会导致重复添加。同公司不同岗位仍可分别收集；公司别名或岗位改名不做模糊合并。提取阶段检查后，正式保存时仍会再次去重。

草稿不会自动进入机会库。保存前至少检查：

- 公司、岗位和工作地点是否正确；
- 截止时间是否真实存在，年份是否正确；
- “岗位亮点”和“门槛与风险”是否来自原文；
- 材料要求和建议任务是否符合实际。

基本字段下方会显示“提取时原文”；材料、任务、亮点和风险的依据可在“提取时的字段依据”中展开查看。“未找到原文依据”意味着需要重点核对，而不是招聘方没有该要求。依据只保证这句话出现在来源正文里，不保证系统理解正确；修改字段后请自行重新核对原文。

AI 返回错误数组、无效日期或超长内容时，系统会提示并自动使用本地规则，你仍可纠正后保存。AI 自评不是系统验证的准确率；未提供自评时不会编造百分比。AI 草稿中只有日期的截止时间按上海时区当天 23:59 处理，建议任务不是招聘方的硬性要求。

公司、岗位、地点会与正文核对；缺少原文支持时会回退到原文可核对的规则结果或留空。截止时间以原文中明确的报名截止或报名时间段为准，保留原文的时分秒；无法确定时留空。若校正了 AI 截止时间，会同时清空可能受它影响的建议任务时间。复杂表述仍需人工核对。

规则提取的日期同样按上海时间处理，只有年月日时取当天 23:59；不存在的日期或时分会留空，不自动改成另一天。原文省略年份时，规则先取当前上海年份，若已过期超过 30 天则尝试下一年；这是推测，请务必核对原招聘公告。

匹配度与兴趣度必须由你自己评分。建议使用以下口径：

- 1 分：明显不匹配或没有兴趣；
- 3 分：可以考虑，但需要权衡；
- 5 分：目标高度一致，愿意优先投入。

最后选择“值得投入”“暂缓观察”“不再考虑”或保留“还没判断”，并写下一个可以执行的下一步，例如“向师兄确认岗位是否接受应届生”，不要只写“准备一下”。

选择“不再考虑”后，机会会归入“未通过/放弃”，不再出现在今日焦点、停滞检查、提醒和有效漏斗中；记录本身仍会保留，便于以后复盘。

编辑机会的公司、岗位或来源链接时也会检查重复。若与已有机会冲突，修改不会保存，输入仍保留；请核对并纠正后再保存。使用 `#/job/…` 等路由的不同岗位链接会保留各自标识，不会因为属于同一个网站而被合并。

### 3.4 找回未确认草稿

已提取但尚未确认的草稿保存在本机。关闭收集窗口后，到“机会库”的“待确认草稿”点击“查看草稿”，可“继续核对”或“移除草稿”。列表每次读取 20 条，点击“加载更早记录”继续查看；“刷新记录”回到最新列表。移除前会确认，不会删除正式机会或本机文件。另一窗口更新草稿后，旧列表的移除操作会被拒绝；请点击“刷新记录”，核对最新内容后重新确认移除。升级程序后请刷新已打开的页面。

继续核对只恢复上次提取结果；关闭前尚未保存的手动修改不会自动保留。恢复后仍需核对原文、补齐公司与岗位等必填信息，再保存到机会库。旧草稿格式不兼容时会保留来源正文供重新整理，成功后更新原草稿。待确认草稿不计入求职漏斗，也不触发机会提醒。

“返回来源”会保留实际读取的招聘正文。修改后再次整理会更新同一份待确认草稿；其他窗口已修改、确认或移除它时，会提示冲突并保留当前输入，请从草稿列表载入最新内容。

## 4. 每日工作流

每天打开应用后先看“今日焦点”。

页面在前台时每分钟自动读取最新数据；切回窗口或重新显示标签页时也会刷新，后台隐藏时暂停轮询。今日排序、截止风险与停滞判断会随读取重新计算，不需要为跨日变化重新启动服务。自动刷新保留正在编辑的输入，不会自动提交。

机会信息、快捷投入决策、个人备注与复盘使用字段级编辑保护：只提交你实际修改的字段。另一窗口修改了不同字段时，两边可以分别保存；如果同一字段已变化，保存会被拒绝，整个操作都不写入，输入仍保留。招聘阶段 / 结束原因 / 投入决策，以及下一步标题 / 时间分别作为关联组核对，避免旧计划把已完成的任务重新变成下一步。

发生冲突后，页面尝试读取最新内容，并在“编辑冲突提示”中展示已保存值。先复制或核对自己的输入，再点“放弃编辑并载入最新”；确认后会放弃本次未保存修改，重新编辑并保存。取消确认会继续保留输入。自动刷新和重复点击保存不会把旧输入自动改为已核对，也不会强制覆盖新值。未作修改时不产生新的保存记录。

任务、招聘节点、材料、岗位要求和设置也使用相同保护。任务与节点的名称 / 时间 / 状态、材料的路径 / 版本、岗位要求的关联 / 就绪状态分别作为关联组核对；修改其中一项时，相关项变化也会提示冲突。标记材料就绪前还会核对关联材料的路径与版本，选择或取消下一步会核对原来的重点任务，避免对已经改变的计划误操作。

删除机会、材料或岗位要求时，会核对你打开确认时看到的记录；机会新增任务、节点、要求或记录，材料的关联及就绪情况变化，也会阻止过期的删除。遇到提示，先关闭编辑或删除窗口，核对最新内容，再重新打开并确认，不能不断点击旧确认绕过保护。

升级后请刷新所有已打开的旧页面，新保护不适用于未升级的旧客户端。系统不提供多人协作或自动冲突合并。未保存输入仍只在当前页面内存中，刷新或关闭页面会丢失，必要时先复制留存。设置页可点“载入最新设置”；存在未保存修改时须确认放弃，密钥输入也会清空。未配置接口时输入框留空、显示默认地址提示；仅修改停滞复查天数不会改写 AI 配置。

服务暂停或读取失败时，已显示的数据会保留，并提示“重试刷新”。保存已经成功但列表未刷新时仍须点击提示中的“重试刷新”，自动轮询不会绕过这个保护，也不会重复提交保存。

机会详情的“节点与记录”中，推进记录按需读取，每页 20 条；点击“加载更早记录”查看历史，失败可重试且已加载内容不会丢失。“刷新记录”回到最新记录。分页只影响显示，完整 JSON 备份仍包含全部活动与草稿。

1. 顶部深绿色区域取“推进清单”的第一项作为焦点，并说明推荐理由和准确时间，不会只因为一个岗位刚收藏就忽略迫近的面试或截止。
2. 清单合并未完成任务、一周内的招聘节点、尚未投递机会的临近截止及有内容的下一步。顺序为：逾期 → 72 小时内 → 7 天内 → 明确的下一步 → 其他任务。一周后的招聘节点和投递截止收在“后续日程”中，临近时自动进入清单。同组依次比较机会优先级（重点优先）、准确截止时间、最后活动时间；只有前面条件都相同时，久未推进才会提前。默认展示前 7 项，可点击“查看全部”展开。
3. 任务（包括下一步）和节点可点圆形按钮或焦点区按钮标记完成，保存成功后下一项接替；失败会显示错误，可刷新核对再重试。投递截止不是任务，请点“查看机会”核对投递状态。没有关联岗位的独立任务也能成为焦点，不会误关联其他岗位。
4. “待判断收件箱”只包含活跃且未作判断的机会，按相同截止规则排列。只有清单为空时，首页才推荐做投入判断或复查现有进度；全是已结束记录时会显示“当前没有待推进事项”，不会要求继续处理已放弃岗位。
5. “风险雷达”优先列出 7 天内的任务、节点、截止和下一步风险，再列超过设置天数未推进的机会。同一机会只出现一次，展示最优先事项的理由。超过默认 5 天未推进才进入停滞复查，可在设置页修改阈值。

进入已投递、测评/笔试、面试、结果待定或 Offer 后，投递截止退出催办清单；跟进任务、签约、体检等节点仍按原计划显示。已放弃机会及已完成/跳过事项不显示。“逾期 / 72小时”和清单数量按事项统计，不是岗位数量，同一机会可包含多项；材料就绪率不包含已放弃机会，仍包含 Offer 后的材料要求。

首页每 30 秒更新当前时间分组与停滞判断；数据在操作后、前台每分钟以及切回窗口时读取。如另一个窗口修改数据，可等待自动读取；读取失败则点击提示中的“重试刷新”。自动读取不会覆盖编辑中的输入，整页刷新前应先留存未保存内容。未定时间的行动任务仍保留在清单中；远期招聘节点与截止日期可展开“后续日程”查看。

## 5. 机会工作区

从首页或机会库点击岗位卡片进入工作区。

### 决策与行动

这里集中显示下一步、投入判断、匹配度、兴趣度、岗位亮点、门槛、任务和材料缺口。第一次进入时，优先完成判断和下一步，不必一次填满所有字段。

### 下一步就是一项真实任务

- 点击绿色卡片上的“安排下一步 / 修改计划”，填写行动及上海时间；保存后同步到行动任务、今日清单、时间线和到点提醒。
- 已有任务无需重复输入：在行动列表点击“设为下一步”。每个岗位最多一个下一步重点，不会覆盖其他岗位。
- 点击任务旁的铅笔，可以修改任务名称、上海时间和预计耗时（分钟）；未作修改不能重复保存。编辑当前重点任务时，下一步卡片会同步更新名称和时间，不会额外创建一项任务。
- 首页“完成这一步”或详情“完成下一步”会完成真实任务，并清除卡片上的旧计划。跳过也会清除重点，任务仍作为历史保留；恢复任务不会自动重新设为下一步。
- “取消重点”或清空下一步内容只取消指定，不删除任务。原任务仍待办，若有到期时间仍会提醒；若不再需要，应完成或跳过任务。单独清空计划时间则保留行动，不发送到点提醒。
- 更新旧版本时会把原计划转换为真实未完成任务；兼容的同名待办优先复用，不改动原任务完成历史及最近推进时间。无需重新录入，也不会把旧计划和任务重复列两次。

下一步是岗位内重点标记，不是强行置顶首页：首页仍按逾期、临期、优先级等统一排序。

### 节点与记录

添加笔试、一面、二面、体检、政审、签约等时间节点。每次沟通、状态变化或重要反馈都应追加一条推进记录，这会更新“最近推进”时间并避免误报停滞。

完成任务、完成招聘节点或标记材料就绪也会自动形成推进记录并刷新活跃时间，不需要重复手写一遍。

### 岗位原文

保留招聘正文、个人备注和复盘。结束后可记录未通过原因、面试问题、准备不足和下次改进点。

三个标签在查看和编辑状态下都会显示对应内容，切换时回到顶部。编辑期间，“决策与行动”修改岗位与行动信息，“岗位原文”修改正文、来源和备注，“节点与记录”管理招聘节点和推进记录。跨标签的岗位编辑输入会保留，点击“保存全部修改”统一保存；节点与推进记录仍通过各自按钮提交。

### 修改阶段

点击顶部“编辑”可以修改大阶段、投入判断、评分、截止时间、下一步以及亮点和风险。阶段统一为：待评估、准备中、已投递、测评/笔试、面试、结果待定、Offer、未通过/放弃。

选择“不再考虑”时，编辑表单会立即显示“未通过/放弃”。如果保留“不再考虑”却选择其他阶段，界面会说明冲突并暂停“保存全部修改”；请把投入判断恢复为“待判断”“值得投入”或“暂缓”，再保存目标阶段。后台也会拒绝矛盾的状态更新，不再显示成功后悄悄改回终态。

机会库按关键词、投入判断和招聘阶段共同筛选；修改后从旧阶段的结果中消失属于正常行为，请切换到新阶段查看。搜索会忽略关键词首尾空格及英文字母大小写，只有空格时视为未输入关键词。卡片和列表使用同一套筛选规则。

每张机会卡片固定显示招聘阶段、投入判断和优先级；有明确发生时间时显示投递时间或阶段更新时间。最近一条推进记录会显示为“最近进展”，没有记录时显示个人备注。“常规”表示优先级。

待评估和准备中的机会可点击“记录投递”，选择今天、昨天或填写真实投递时间，勾选确实完成的投递相关任务，并可一起安排下一步。只完成勾选项，其余任务保留。状态、实际日期、任务与新计划会一起保存，失败时整体回滚。实际发生时间与本次录入时间分别记录。

已投递及后续阶段可点“核对投递任务”集中处理遗留任务，不限于原先的下一步；可点“安排跟进”创建新的下一步并设置提醒时间。“记录进展”支持测评/笔试、面试、结果待定及 Offer；记录邀请时，可以同时安排未来的招聘节点。旧阶段日期未知时，同阶段的有效补录会补齐卡片日期；已有明确日期的当前阶段不会被旧经历覆盖。

在“节点与记录”填写推进记录，或在“岗位原文”保存个人备注时，可以同时选择要同步的招聘阶段。输入“已投递”等文字会提供“同时标记为已投递”入口，点击后再保存才会同步；默认保持当前阶段。状态和记录一起保存，失败时整体回滚；另一窗口已修改状态时会拒绝覆盖并保留输入。

### 阶段历史与真实复盘

当前阶段表示“现在在哪一步”，阶段历史表示“明确经历过什么”。在详情顶部点击“编辑”，修改阶段并“保存全部修改”后，原阶段、目标阶段与变更时间会一并记录。退回准备中不会抹掉投递或面试经历；重复进入同一环节，复盘人数仍只算一个机会。

详情 →“节点与记录”→“阶段历史”显示最高有效记录，以及每次经历的来源、发生时间和记录时间：

- 点击“补录经历”，选择已经发生的阶段，填写上海时间或留空表示未知；备注可记录凭据。保存不改变当前阶段。
- 未来面试、笔试等安排仍添加“招聘节点”，不能作为已发生经历补录。
- 误录时点击记录旁“作废”，填写原因并确认。原记录保留但不再参与统计，原因记录在推进记录中；这不会改变当前阶段。当前阶段也选错时需另行编辑。
- 旧库和旧 JSON 只能还原明确的当前阶段，未知此前经历不会自动补齐。旧快照的“依据时间”是原记录更新时间，不是招聘阶段的发生时间。中途建档为面试或 Offer 时也不会自动补造投递、笔试、面试记录；可按真实经历补录。

机会结束时，在编辑信息中选择“结束原因”：未通过、主动放弃或尚未确认。“不再考虑”会自动归为主动放弃。重新开启时应同步调整投入判断和阶段。

“复盘”默认排除主动放弃，保留未通过和未分类结束，避免只看成功机会；可切换“全部机会”。所有人数、结果卡片使用同一筛选范围，并按有效历史对机会去重：

- 投递率：有投递记录的机会 / 库内机会。
- 测评率：同时有投递与测评记录的机会 / 有投递记录的机会。
- 面试率：同时有投递与面试记录的机会 / 有投递记录的机会，允许跳过笔试。
- Offer 率：同时有面试与 Offer 记录的机会 / 有面试记录的机会。

各环节显示全部已记录人数；百分比只计算分子、分母都有记录的机会，因此不会超过 100%，没有分母显示“—”。跳过环节、晚建档或前史未知时人数可能不逐级递减，不能把未记录当作从未发生。历史与作废状态随 JSON 备份保存；永久删除机会会同时删除它的历史。

### 保存反馈与重试

保存时按钮和相关输入暂时锁定，避免连续点击；成功显示“已保存”，失败在页面/弹窗内显示原因并保留输入。空名称、无效日期和已删除记录不能静默保存。遇到记录不存在，请刷新核对，不要反复提交旧表单。

如果显示“数据已保存，但列表刷新失败”，这笔写入已完成。关闭详情后点击页面提示中的“重试刷新”，不要重新添加；刷新成功前系统会阻止新写入。

网络中断导致结果未知时，先核对已有记录；同一窗口内保持输入不变后点击重试，会沿用该次提交标识，避免已成功的操作重复写入。刷新页面、新开窗口或修改输入后不能沿用标识，应先确认是否已经保存。设置保存失败也保留输入；若明确提示密钥已写入而其他设置未保存，表示钥匙串已变更、数据库设置未提交，系统不能自动回滚钥匙串。先核对接口、模型及所用密钥，重新载入设置并填写需要保存的配置；已确认密钥正确时可留空密钥输入框，仅保存配置，避免无意再次替换密钥。

## 6. 材料库

材料库只保存本机路径和版本标签。建议材料名称同时体现用途与版本，例如“算法岗中文简历”，版本写“2026-08 v3”。

点击卡片“编辑 / 替换”可修改名称、类型、版本、说明和路径；可通过 macOS 文件选择器重新定位文件，也可粘贴完整路径。取消编辑不保存，保存失败保留输入。每次打开编辑窗口都会读取所选材料，不会沿用上一份材料的草稿。

文件被移动或删除后，卡片会显示“文件已移动”，点击“修复文件引用”替换路径即可；原材料 ID 和岗位关联保留，无需新建重复材料。应用不会恢复、复制或移动实际文件。

卡片显示关联的岗位要求数量。替换路径或版本后，所有关联要求都会恢复“待准备”，请核对新文件后重新标记就绪；只改名称、类型、备注不影响就绪。删除按钮会先确认影响范围：仅移除材料库引用，关联要求保留但取消关联并恢复待准备，绝不会删除本机文件。

“路径存在”只表示文件仍在该位置，不代表已通过安全检查。点击“打开文件”时会检查材料库记录及实际文件；支持 PDF、普通 Office 文档、文本和常见图片，不运行应用、脚本、安装包或带可执行权限的文件，也不支持 DOCM 等含宏格式。文件被改名为 PDF 也不能绕过程序头检查。遇到拒绝时，卡片会显示原因，请重新关联可信材料，不要为了绕过检查修改权限；这不是杀毒软件，请勿启用不可信文档中的宏。

选择文件过程中按钮会显示“选择中…”，取消不会清空已填路径；操作失败会在弹窗内提示，并保留输入。打开文件时按钮暂时锁定，失败信息显示在材料卡片中，不会只弹出系统式警告。

在机会详情的“材料缺口”中，先选择对应材料，再点击“保存关联”；仅切换下拉选项不会写入。关联失败会保留选择，修正后可重试。关联成功后可将该要求标记就绪，这与选择材料是两个独立动作。

岗位要求可在收集后继续维护：下方“添加要求”记录名称及格式、命名、盖章等说明；点击要求旁的铅笔可编辑或移除。移除要求需再次确认，不会删除材料库记录或文件。切换/取消材料关联会恢复待准备；文件缺失会在要求下显示提示。没有电子文件的线下材料也可手动标记就绪，这不是对文件内容、有效期或真实性的自动验证。

另一窗口在你标记就绪前替换了关联材料的路径或版本，本次标记会被拒绝，请核对新材料后再操作。版本保护只比较路径及版本标签：在相同路径直接覆盖文件且不更新版本，系统无法识别内容变化。更换文件内容时请同步更新版本，并人工检查格式、有效期与真实性。

## 7. 时间线与提醒

“时间线”把投递截止、行动任务和招聘节点合并排序。所有日期输入、显示及提醒按上海时间（Asia/Shanghai）处理；即使浏览器或电脑切换时区，输入的 15:00 仍代表上海 15:00。

提醒设置在机会详情中：

- 顶部“编辑”→“投递截止提醒”：默认提前 7、3、1 天及当天的上海时间 09:00。可点选、添加自定义天数、关闭此项或恢复默认。如果当天截止早于 09:00，当天提醒会提前到截止时刻。
- “节点与记录”：新建和编辑面试、体检、签约等节点时，可调整提醒。默认相对节点准确时间提前 7、3、1 天及到点；可选择提前 1 小时、30 分钟或添加自定义分钟数。添加自定义数值后须点击“添加时间”，最后保存节点。未设时间或关闭提醒的节点不会通知；保存失败会保留编辑内容，修正后可重试。
- 未完成任务（包括下一步任务）在到期时提醒一次，同一任务不会再作为独立计划重复通知。完成/跳过任务或清空其计划时间会停止相应提醒。

进入已投递及后续阶段后不再提醒投递截止，但未完成的跟进、面试、体检、签约等节点及任务（含下一步）继续提醒。退回待评估或准备中时恢复投递截止提醒。机会进入“未通过/放弃”或投入判断设为“不再考虑”后，关联提醒全部停止；独立任务不受影响。已完成或跳过的节点也不提醒。

只有本地服务运行时才能发送 macOS 通知，每分钟检查一次，因此可能延迟约一分钟；关闭浏览器不会停止服务。服务重启或长时间暂停后，只发送一条遗漏汇总，不逐条补发，即使停机超过 48 小时也会核对尚未提交的提醒。同一事项多个已过期提醒在汇总中只计一次；已交给系统的同一提醒不重复发送。修改截止/节点时间后会按新时间重新安排，新增已过期时间也可能产生汇总，请确认输入。

“设置与数据”→“时间与系统提醒”可查看最近检查、下一次计划、待提交数量和错误，并手动发送测试通知。测试不会消耗招聘事项的提醒记录；成功后至少间隔 10 秒再测试。显示“已提交”仅表示通知已交给 macOS，不保证系统实际展示。看不到通知时，检查“系统设置 → 通知”中脚本通知发送者的权限和专注模式。测试环境禁用通知时按钮不可用，也不会把事项误记为已提醒。极少数情况下，服务在通知提交后、记入数据库前崩溃，恢复时可能再次提交一次。

## 8. 备份与恢复

在“设置与数据”中：

- “导出完整 JSON”用于完整恢复；
- “导出机会 CSV”用于 Excel 查看或归档，包含投入判断、评分和下一步；
- “恢复 JSON 备份”会替换当前全部数据，操作前会再次确认；文件上限为 50 MB。

恢复会先校验字段类型、真实日期、阶段/状态、唯一标识和机会/材料关联，再在临时数据库试恢复并逐字段核对。普通备注、正文、公司名等文本不会被当成日期转换。校验或写入失败时，当前数据保持不变；界面会显示错误位置，同一个文件修改后可以重新选择。

替换前会自动在 `~/Library/Application Support/ZhaopinAssistant/backups/` 保存 `before-restore-…` 快照：

- `.sqlite`：完整的恢复前数据库快照，包括尚在 WAL 日志中的已提交内容；文件只允许当前用户读写。
- `.json`：原数据可正常读取并通过校验时，同时生成可再次导入的 JSON。误选备份后，可在设置页选择对应的 `.json`，恢复到替换前状态。

恢复完成后，界面显示可用于回退的快照路径，并自动刷新数据与设置。如果当前数据库已经损坏而只有 `.sqlite` 快照，请保留该文件，交由维护人员离线检查；不要把它当 JSON 上传，也不要直接覆盖正在运行的 `app.db`。自动快照不会自动清理，可在确认无需回退后自行归档或删除。

若网络中断，界面可能无法确认服务端是否已恢复。先确认服务运行并刷新核对数据，不要直接重复恢复；若显示“数据已恢复，但列表刷新失败”，只需重试读取列表。

建议每周导出一次 JSON，并保存在项目目录之外。备份包含设置和材料路径，不包含钥匙串中的 API 密钥或材料文件本身；换机器后须重新配置密钥并核对文件路径。恢复前快照与数据库同机存放，不能替代异机备份。

## 9. 常见问题

### 提示“请求来源不受信任”

请直接打开 `http://127.0.0.1:3000` 并刷新工作台。其他网页、嵌入页面、不同本机端口或自定义域名不能调用工作台接口。不要混用 localhost 和 127.0.0.1 的页面与接口地址，也不要通过代理暴露服务；从工作台里的“设置与数据”正常导出备份不受影响。

### 链接显示无法读取

应用已经会自动尝试加载动态页面；仍然无法读取时，提示会说明登录、验证码、岗位失效、超时或组件启动问题。按界面指引粘贴岗位正文即可继续，链接仍然保留。

### 提示“为保护本机安全，不能读取这个地址”

平台只自动读取普通公网 HTTP/HTTPS 页面，不连接本机、内网、特殊用途地址或非标准端口；公开链接跳转/解析到这些地址时也会停止。不要尝试关闭安全限制。保留链接，直接粘贴招聘正文即可继续整理，此时不会自动访问该来源链接。

如果网络代理把域名解析成内部或特殊地址，自动读取也可能被拦截，请使用正文粘贴。招聘抓取不使用环境代理，也不会绕过登录或验证码。

### 提示页面太大、超时或跳转过多

单页下载及解压后的体积分别限制为 2 MB，网络读取总时限为 12 秒，最多跟随 5 次跳转。超过限制会停止自动读取并保留输入，不会创建正式机会。复制所需的岗位正文后重试即可。

动态浏览器读取另有 40 秒时限、100 个请求、48 MB 总资源及单资源 12 MB 限制，避免页面持续加载占用本机资源。

### 腾讯招聘链接无法读取

当前版本已针对 `careers.tencent.com/jobdesc.html?postId=...` 使用官方岗位接口。如果仍失败，岗位可能已下线或腾讯接口临时不可用，可粘贴正文兜底。

### 页面打不开

再次双击 `start.command`。若仍失败，先查看 `~/Library/Application Support/ZhaopinAssistant/launcher.log`；若提示服务进程退出，再查看同目录的 `server.log`，或按开发手册的排障步骤处理。

### 数据存在哪里

数据库默认位于 `~/Library/Application Support/ZhaopinAssistant/app.db`。完整备份仍应通过设置页导出，不建议直接复制正在写入的数据库文件。

### 启动时提示数据库迁移失败

正常启动会自动检查并升级数据库，无需手动重新录入。升级结构和成功记录一起保存；本批升级失败会回滚，程序会停止启动并说明原因。如果提示迁移文件被改动、结构不兼容或程序版本过旧，请保留 `app.db`、`backups/` 和启动日志，让维护人员恢复匹配的项目文件或检查备份。不要删除数据库、清空迁移记录或强行启动旧版本。已有记录再次启动不会重复执行任务/历史转换。

### 维护测试会影响我的数据吗

项目的 `npm test` 和 `npm run test:e2e` 会自动创建独立临时库，不使用你的求职数据、真实 AI 密钥或系统通知。端到端测试在临时项目副本中运行，正式工作台可以保持开启。测试临时库正常退出后清理，截图与日志留在项目的测试报告中；这不会删除你的岗位、任务或材料。直接运行其他调试脚本仍须按开发手册隔离环境。

### 安全更新后如何使用

正常打开“求职助手.app”或 `start.command`，入口会检查当前版本并完成必要更新；不需要重新录入数据。2026-10-03 的依赖修复不改变界面、数据格式或 AI 设置方式。维护人员更新依赖时会暂时停止服务并重新构建，完成后重新启动；关闭期间不会发送提醒，重启后仍按原有遗漏汇总规则处理。请不要自行执行 `npm audit fix --force`，这可能安装不兼容版本。
